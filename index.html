APPLIED AI / TREASURY COPILOTHackathon · July 2025

Ask like a treasurer.
Act through APIs.

Banking capabilities live behind technical interfaces. I explored a conversational entry point: a Treasurer persona that uses retrieval to find relevant context and MCP tools to connect user intent with banking API execution.

✦ Most Innovative Solution · Hackathon recognition
INTENT → CONTEXT → TOOL → ACTIONINTERACTIVE WALKTHROUGH
“Help me make a payment using the bank’s Move Money services.”
01 / UNDERSTAND

Start with the business intent.

The Treasurer persona interprets the request as a payment task. The conversation gives the user a familiar starting point for discovering a banking capability.

Illustrative walkthrough of the prototype architecture. This page does not call a model, connect to a bank or execute a payment.

Behind the conversation
  1. 01 / INTENTTreasurer persona

    Interpret the banking task in context.

  2. 02 / CONTEXTRetrieval augmented generation

    Bring relevant banking material into the conversation.

  3. 03 / TOOL DISCOVERYMCP client & server

    Expose banking capabilities as tools the agent can use.

  4. 04 / API ACTIONMove Money APIs

    Connect the selected tool to a banking API call.

3 APIs

A concrete banking scope

Three Move Money APIs gave the prototype a defined execution surface and a focused treasury use case.

MCP + RAG

Context and capability

An MCP server and client connected tools. Retrieval supplied relevant context for the Treasurer experience.

Intent → Action

My build focus

Connect the persona, conversational interface, retrieval and API tools into an end to end hackathon prototype.

The next product question: can users trust the action?

For a production treasury experience, the design would need to make missing details, tool permissions, payment confirmation and execution evidence visible. The prototype established the interaction pattern; those controls are the next design and engineering step.

Prototype scope and recognition are from my project record. This case study describes an exploration, with production controls identified as future work.
